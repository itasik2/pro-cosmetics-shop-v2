# Pro Cosmetics Shop — Next.js eCommerce (Starter)

Минимальный рабочий прототип магазина профессиональной косметики.

## Запуск локально

1. Скопируйте `.env.example` в `.env` и при необходимости поменяйте значения.
2. Установите зависимости:
   ```bash
   npm install
   ```
3. Примените схему БД и засеять данные:
   ```bash
   npm run db:push
   npm run db:seed
   ```
4. Запустите dev-сервер:
   ```bash
   npm run dev
   ```
5. Откройте: http://localhost:3000

### Admin
- Страница: `/admin`
- Вход: через Credentials (см. `.env`: `AUTH_ADMIN_EMAIL`, `AUTH_ADMIN_PASSWORD`).
- Можно создавать/редактировать товары, удалять.

### Безопасный автопилот каталога

- Ежедневный cron ищет данные для новых импортированных товаров, проверяет изменения источников и обрабатывает ожидающие предложения.
- Текст применяется автоматически только при совпадении не ниже 90%, с включённого официального источника и после проверки структуры/качества.
- Автопилот изменяет только краткое и полное описания. Фото, цена, остатки и статус публикации не меняются.
- Совпадение 0% отбрасывается, низкое совпадение один раз запускает поиск другого источника, остальные спорные случаи остаются в очереди администратора.
- Временные ошибки сети и API повторяются автоматически, но не более трёх раз подряд.
- Последние автоприменения видны в `/admin/enrichment`; текст можно откатить, если после него не было ручной правки.
- Аварийное отключение: `CATALOG_AUTOPILOT_ENABLED=false`.

### Автоматический блок популярных товаров

- Отдельный ежедневный cron оценивает актуальный интерес в сети небольшими партиями и работает только с опубликованными товарами, которые уже есть в каталоге.
- Товар автоматически получает отметку «Популярный» только при оценке от 65%, уверенности от 70% и минимум двух независимых подтверждениях.
- Сетевой монитор не создаёт товары и не меняет описание, фото, цену, остаток или статус публикации.
- Ранее выбранные вручную популярные товары закрепляются и не снимаются автоматикой. Если снять отметку вручную, монитор не добавит этот товар обратно без нового ручного включения.
- Аварийное отключение: `CATALOG_POPULARITY_MONITOR_ENABLED=false`.

## Почта заказов (Zoho SMTP)

Для `procosmetics.kz` адрес получателя и SMTP-пользователь по умолчанию — `sales@procosmetics.kz`, сервер — `smtp.zoho.com:465`. В Vercel достаточно добавить секрет `SMTP_PASSWORD_PROCOSMETICS` с паролем приложения Zoho. При необходимости остальные параметры можно переопределить переменными из `.env.example`.

- Ежедневный мониторинг проверяет главную страницу, каталог, базу данных и sitemap. При первом сбое и последующем восстановлении отправляется письмо администратору.
- Каждый понедельник в 09:30 по времени Алматы на административную почту приходит отчёт за 7 дней: контрольные проверки, скорость ответа и статистика заказов.

### Отзывы клиентов

- Публичный блок временно скрыт, но отзывы, API и административный раздел сохранены.
- После внедрения регистрации блок можно вернуть переменной `PUBLIC_REVIEWS_ENABLED=true`.

### Stripe
- По умолчанию выключен (нет ключей). Добавьте `STRIPE_SECRET_KEY` и `STRIPE_PUBLIC_KEY` для тестовых платежей.
- Оплата в тенге (kzt).

### Переключение на PostgreSQL
- В `prisma/schema.prisma` замените `provider = "sqlite"` на `provider = "postgresql"` и выставьте `DATABASE_URL` для Postgres.
- Затем: `npm run db:push`.

### Деплой
- Рекомендуется Vercel. Укажите ENV переменные.
- Перед production-сборкой выполняется preflight-проверка `DATABASE_URL` (`npm run check:env:build`) — это помогает упасть раньше и с понятной ошибкой, если переменная не задана.
- Для корректного SSR укажите `NEXTAUTH_URL` на ваш домен.

### Multi-site (один шаблон → несколько сайтов)
- Поддерживается запуск одного кода для разных витрин через `SITE_KEY`.
- Пример: `SITE_KEY=procosmetics` для procosmetics.kz и `SITE_KEY=fitoapteka` для fitoapteka.kz.
- Для каждого деплоя (например, в Vercel) задайте свои ENV: `SITE_KEY`, `SITE_TITLE`, `SITE_DESCRIPTION`, `NEXT_PUBLIC_SITE_BRAND`, `NEXT_PUBLIC_URL`.
- **Отдельная БД для каждого сайта:** в Vercel-проекте каждого домена задавайте свой `DATABASE_URL` (не делите одну БД между разными сайтами, если хотите полностью изолированный контент/админку).
- **Отдельная админка по доступу:** задавайте уникальные `AUTH_ADMIN_EMAIL` и `AUTH_ADMIN_PASSWORD` для каждого деплоя.
- **Опционально для shared runtime:** можно использовать scoped-переменные вида `AUTH_ADMIN_EMAIL_<SITE_KEY_UPPER>`, `AUTH_ADMIN_PASSWORD_<SITE_KEY_UPPER>`, `ADMIN_EMAIL_<SITE_KEY_UPPER>`, `SMTP_PASSWORD_<SITE_KEY_UPPER>`.
- API настроек сайта (`/api/site-settings`) и тема читаются/сохраняются отдельно по `SITE_KEY`, поэтому контент и оформление не смешиваются между сайтами при общей кодовой базе.

### Быстрое обновление `fito-apteka-shop-v2` по этому шаблону
1. Создайте отдельный Vercel-проект и отдельную БД для `fito-apteka-shop-v2`.
2. Установите ENV минимум:
   - `SITE_KEY=fitoapteka`
   - `NEXT_PUBLIC_SITE_BRAND=fitoapteka.kz`
   - `NEXT_PUBLIC_URL=https://fitoapteka.kz`
   - `DATABASE_URL` (своя, отдельная)
   - `AUTH_ADMIN_EMAIL` / `AUTH_ADMIN_PASSWORD` (свои)
3. Выполните миграции Prisma в окружении fito-проекта.
4. Проверьте `/api/site-settings` и админку `/admin` — настройки и доступ должны быть изолированы от procosmetics.

## Подбор ухода и условия покупки

- `/care` подбирает товары по задаче, типу средства и бюджету. Это фильтр по данным каталога, а не диагноз или назначение лечения.
- Фильтр «В наличии» учитывает фасовки: товар с доступным вариантом не пропадает из каталога из-за нулевого общего остатка.
- `/delivery` раскрывает условия доставки и оплаты. Настройки магазина: `STORE_DELIVERY_TERMS`, `STORE_RETURNS_TERMS`, `STORE_SELLER_NAME`, `STORE_SELLER_ID`, `STORE_SELLER_ADDRESS`. Поддерживаются scoped-переменные `_PROCOSMETICS`.
- `STORE_DELIVERY_PRICE` — подтверждённый единый тариф в целых тенге. `0` означает бесплатную доставку, пустое значение — стоимость требует уточнения. При заданном тарифе сервер включает его в итог и сохраняет в `Order.shippingPrice`; браузер не задаёт стоимость. Не используйте единый тариф, если он зависит от города или веса.
- При пустом тарифе корзина и оформление показывают стоимость товаров без доставки и предлагают уточнить доставку до оплаты. Автоматический расчёт по QazPost требует договора, тарифов и веса упаковок; этот релиз не имитирует ответ перевозчика.
- Сведения о продавце выводятся только после заполнения подтверждённых значений. В проект не добавляются вымышленные реквизиты, обещания подлинности или сроки доставки.
- Блог поддерживает Markdown/GFM (таблицы, списки, выделения). HTML из статьи не исполняется.
- Неполные автоматические описания отправляются на ручную проверку. Исходные тексты товаров сохраняются; редакторские заметки не выводятся как преимущества.
- Для известной неполной карточки азелаинового крема Angiopharm отображается инструкция, сверенная с официальной страницей производителя 06.10.2026, со ссылкой на источник. Полные ручные описания не заменяются.

Проверка регрессий: `npm run test:store`. Сборка preview не применяет миграции к базе.
# ИИ-консультант магазина

`/ask` подбирает опубликованные товары по задаче, типу, бренду и бюджету из вопроса и последних реплик покупателя. Учитывает доступные варианты, исключает объединённые карточки и проверяет возвращённые моделью ID. Цены, объёмы, остатки и кнопки корзины формируются на сервере из каталога; стоимость и сроки доставки передаются из `STORE_*`. Служебные сообщения о неполных данных не используются, инструкция азелаинового крема совпадает с публичной карточкой.

С формы `/care` можно перейти к ИИ с выбранными фильтрами. Из карточки товара открывается консультация с контекстом этого товара. Медицинские запросы передаются специалисту без генерации лечебной схемы. Если ключ или провайдер недоступен, показывается честное сообщение и, когда это возможно, обычный подбор по фильтрам. Рекомендации без отдельных ингредиентов требуют сохранённого состава и источника.

Серверные переменные (поддерживают суффикс сайта): `OPENAI_API_KEY`, `OPENAI_ASK_MODEL` (по умолчанию существующая `gpt-4o-mini`), `AI_CONSULTANT_ENABLED=false` для отключения, `AI_CONSULTANT_DAILY_LIMIT` (по умолчанию 200 вызовов модели на сайт в сутки UTC). Также действуют 5 запросов в минуту и 30 вызовов модели в сутки на IP. Одна генерация ограничена 1000 токенами ответа и 25 секундами, повторные вызовы автоматически не выполняются. DB rate limits общие для экземпляров приложения; при недоступности таблицы остаётся существующий локальный fallback, поэтому это не гарантированный финансовый лимит — настройте бюджет у провайдера. Ограничение по IP может затронуть покупателей за общей сетью.

Диалог хранится только в состоянии открытой страницы и отправляется провайдеру для ответа; в базе диалоги не сохраняются. Пользователь видит уведомление о передаче сообщений ИИ. Консультант не создаёт заказ и не отправляет сообщение в WhatsApp автоматически. Данные каталога и ответы ИИ могут быть неполными; интерфейс предлагает уточнить сведения у магазина.

Проверки: `npm run test:store` включает сценарии поиска, бюджета/вариантов, ограничения состава, истории, проверки ID, отказов провайдера и структурированного ответа. Проверку живой генерации выполняйте без персональных и медицинских данных.
