# Универсальный черновик поставщика и обогащение

На `/import` результат любого поддерживаемого парсера преобразуется в JSON
`catalog-hub/supplier-draft`, версия 1. Выгрузка содержит идентификаторы, вариант
упаковки, цены, исходные суммы без назначения, колонки и координаты источника,
ошибки сопоставления и недостающие поля. Это внутренний черновик с закупочными
ценами, не файл маркетплейса. Повторный импорт вложенного JSON пока не подключён.

Отсутствующий остаток остаётся неизвестным. В созданную карточку не переносится
остаток поставщика. Генерируемый SKU не записывается как артикул поставщика.
Для новых карточек объём и источник сохраняются в `attributes.volumeValue`,
`attributes.volumeUnit` и `attributes.supplierImport`. У существующих товаров
импорт по-прежнему изменяет только сопоставленные поля.

После сохранения товара ссылка открывает `/ai` с его SKU. Можно настроить
доверенные сайты поставщика, выбрать набор источников, добавить задачу,
запустить или повторить поиск. Автоматический поиск по официальным доменам
требует `OPENAI_API_KEY`. С явной ссылкой на разрешённый товар извлечение HTML
работает и без ключа, с описанием из исходных данных. Для дистрибьютора на этом
этапе требуется ссылка на товар. Внешний поиск из интерфейса отключён.

Предложение показывает источник, совпадение, предупреждения, тексты до/после
и фотографии. Черновик заполняет пустые поля. Замена текста/фото требует
переключателя. Цены, штрихкоды и остатки не входят в патч обогащения.
Категория пока задаётся через редактор товара. Изменения нужно согласовать
и применить. Фотографии выбираются вручную без генеративной обработки.

## Локальный запуск

`npm run local:dev` автоматически запускает Node-сервис обогащения на
`127.0.0.1:8001`, если `.env.local` указывает на изолированный Docker API
`http://127.0.0.1:8000` и включён локальный режим. Node использует только
тестовую БД `127.0.0.1:55432/catalog_test`. Зависимости устанавливаются
командой `npm run testdb:setup`. Для автоматического поиска добавьте
`OPENAI_API_KEY` в `.env.local`; ключ передаётся только серверу.
Остановка local:dev останавливает оба процесса.

Основной API обслуживает импорт и UUID-изменения. ИИ-задачи, источники и CUID-
изменения обслуживает Node с той же БД. В другой среде дополнительный адрес
задаётся через `CATALOG_HUB_AI_API_URL`; удалённый адрес в локальном режиме
запрещён. Рабочая Supabase этим этапом не разворачивается и не меняется.

## Проверки

- Web: npm test, npm run typecheck, npm run build.
- Node: npm run prisma:generate, npm test, npm run typecheck.
- После testdb:setup / testdb:use и запуска local:dev:
  `node catalog-hub-local/enrichment-e2e.mjs`.

Интеграционный сценарий проверяет источники, очередь, изоляцию организаций,
отказ недоверенного домена, выбор фото, staging, согласование, применение
и прежние цены/остатки. Используется синтетическое предложение без внешних
сайтов и платных ИИ-вызовов. Качество поиска нужно отдельно проверить на
прайсах и разрешённых страницах поставщиков.
