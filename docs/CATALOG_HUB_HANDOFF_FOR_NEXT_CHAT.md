## Главная концепция

Catalog Hub — **самостоятельный универсальный B2B-продукт** для управления товарами, вариантами, прайсами поставщиков, фотографиями, ИИ-описаниями, ценами, физическими остатками, заказами, маркетплейсами и интернет-магазинами.

**Не путать:** Catalog Hub ≠ ProCosmetics. ProCosmetics — первый подключаемый OWN_STORE-клиент, а не основа всех бизнес-правил. Marketplace Hub — будущий адаптерный/канальный слой, **не отдельный мастер-склад или вторая система заказов**. Kaspi, Ozon и Wildberries подключаются на равных правах через адаптеры. Цель — продавать сервис разным организациям Казахстана.

В настоящий момент код Catalog Hub ещё находится в монорепозитории ProCosmetics. **Не переписывать всё с нуля и не переносить без отдельного плана**. Проектируем самостоятельность сразу, выделяем физическую кодовую базу контролируемо.

## Что ещё не завершено

1. Универсальный безошибочный импорт сложных поставщицких прайсов: PDF/Excel/XML/CSV и сопоставление колонок.
2. Стабильный подбор фотографий конкретных вариантов и объединение дублей с сохранением цен/артикулов.
3. Покупательские описания без неподтверждённых обещаний, правильное разделение описания, применения и INCI.
4. Надёжное управление складами и заказами без двойного списания.
5. Независимость ядра от ProCosmetics и реальный универсальный контракт каналов.
6. Пилот ProCosmetics через OWN_STORE без циклического dual-write.
7. Подключение Kaspi через разрешённые API/XML и безопасная публикация с журналом.
8. Репрайсер с источниками конкурентов, границами маржи, проверкой устаревших наблюдений и защитой от убыточной цены.
9. SaaS: несколько организаций, роли, RLS, лимиты, подключение магазинов.

**Не начинать с новой интеграции маркетплейса.** Сначала проверить и довести полный конвейер:

**Прайс → распознавание → сопоставление → дубликаты/варианты → ИИ-данные/фото → подтверждение → сохранение и публикация.**

Порядок:

1. Сверить актуальный `main`, текущие PR, Vercel production, версию Edge Function и схему Supabase. Выявить расхождения frontend/API (Edge v20 от 22.10).
2. Выполнить безопасный smoke без записей: дашборд, каталог, категория, импорт preview, ИИ-предложение и медиа.
3. На изолированной локальной БД проверить реальный формат прайсов JeuDerm, Mesaltera, Ангиофарм и Skinosophy (с контрольными строками, фасовками и ценами). **Цена 1/2 только с явным назначением.**
4. Исправлять выявленные ошибки отдельными небольшими PR с тестами; после каждого PR проверять сборку и соответствующий сценарий.
5. Когда P0 закрыт, переходить к инвентарю/резервам, подключению собственных магазинов и Kaspi по этапам полного ТЗ.

## Обязательные ограничения

- Не выполнять production-миграции, массовые операции, реальные выгрузки в Kaspi или замену боевой базы без отдельного разрешения.
- Не смешивать закупку и розницу, склад продавца и наличие у поставщика, master SKU и sellerSku.
- Не публиковать ложные свойства продукта, не подставлять фото соседней фасовки и не заменять ручной выбор категории.
- Не использовать неофициальные методы записи в Kaspi. XML — безопасный базовый маршрут, возможности API требуют проверки.
- Не выставлять секреты в Git/browser/логи; вся SaaS-изоляция по organizationId.
- Различать «код существует», «тесты пройдены» и «проверено на живой интеграции».
- Каждую завершённую задачу фиксировать: PR/commit, что изменилось, тесты, статус Vercel/Edge, миграции, фактические ограничения и следующий шаг.
